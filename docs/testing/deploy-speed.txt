Deployed Feed speed history

Trigger: each successful Production deployment_status event, plus manual workflow_dispatch from main only. The GitHub deployment object exists for Vercel Production (verified 14 Oct). This local candidate has not activated a hosted workflow.

Measurement: public signed-out Feed, Chromium, a fresh context and disabled network cache for each sample. Desktop 1440x900 unthrottled; phone 390x844, 150 ms latency, 200000 download bytes/s, 93750 upload bytes/s and 4x CPU slowdown. Three samples per profile, medians and raw observations. These are lab observations, not real-user monitoring or a physical phone. Compare within a method and account for runner variation.

Method v2 counts preloaded .js/.mjs resources in script bytes as well as script-initiated resources. v1 omitted preloaded scripts in that byte metric. LCP settings are unchanged, but v1 and v2 byte totals must not be compared directly. The method ID changes when settings or metric definitions change.

Object binding: expected full deployment SHA, live /api/health SHA and rendered page meta SHA must agree. Health is read again after sampling. HTTP redirects are checked before following; browser top-level navigation is restricted to https://striverun.app, and the final page URL is checked. External scripts and images may still load from their existing hosts. Wrong SHA, redirected host or missing paint produces a failed record, never a zero or a timing for the wrong version. No sign-in, uploads, credentials or synthetic data are sent to production.

Storage: measurement.json, rolling history.json and history.csv are retained in the strive-speed-history GitHub artifact for 90 days, plus the workflow summary. Every run restores the latest retained snapshot, including failed observations. Serial concurrency prevents racing appends. The two history files together are capped at 10 MB: prune oldest entries until they fit, retain the latest measurement, and record the count pruned. An older over-limit snapshot is pruned on the next append. A single impossible oversized measurement fails explicitly. A retention gap can reset history, marked new-no-retained-snapshot; this is not indefinite storage. Invalid history or a failed artifact restore stops the job instead of silently resetting it. No regression budget is set yet; failures mean invalid measurement, not a guessed speed threshold.

Supply chain: checkout, setup-python and upload-artifact use full commit SHAs with tag comments, resolved from the official actions repositories. Playwright 1.60.0, pyee, greenlet and typing-extensions are version and SHA256 pinned for Python 3.12 on Linux x86_64. pip requires hashes; Chromium is installed by that pinned Playwright package. No browser install on Oscar's Mac: existing local cache is reused.

Tests exercise missing paint, health SHA mismatch, page-meta mismatch, main failure persistence without exception text, redirect rejection, history preservation and oldest-first pruning past 10 MB.
