STRIVE product brief: project updates worth responding to
Draft for review. This describes intended behavior; it is not a claim that every feature is available.

Purpose
STRIVE helps builders show what they are making, explain what changed and ask for useful feedback. Recorded agent activity can support the story. A screenshot or project link can also be a useful update without connecting an agent.

Landing
Post your strides.
Show what you're building. Get useful feedback.
A project, a real screenshot, and what changed—with recorded agent activity when you have it.
Primary action: Create a private preview
Secondary action: Explore projects
Choose what to upload. Sharing is a separate step.

The project card
A reader first sees the project and its purpose, a real product visual, what changed and one specific question. Supporting recorded facts and an activity trace follow. A project history connects successive updates without merging unrelated measurements.

Use existing white cards, blue activity traces and shared renderers. Frame the entire supplied image automatically from its dimensions. Keep screenshot captions outside the image and offer full-size opening. Show only useful known headline facts; explain missing or withheld measurements in the evidence details.

A Manual update uses author-supplied screenshots, links and description. It has no inferred tokens, duration, model or commits. A Captured session identifies its actual source and selected window. Neither source label means provider verification or independent proof of task success.

Profiles
A profile contains a short bio, projects and optional author-chosen external links. A pasted link is not proof of account ownership. Connected status requires an actual supported authorization or ownership check and a disconnect action. Adding a connector is optional.

A useful return visit
A builder returns to the same project, records the change since the last update and responds to a specific reader suggestion. A reader can follow that project and understand whether the suggestion was tried. Retention must be tested through actual repeat use; feature availability alone does not establish it.

Entry and setup
Offer Add a project update alongside Use a recorded session. Manual updates need no agent connection. Saving requires the appropriate account session; preview and useful local export should be available before registration where supported.

For recorded work, select a project and a bounded recorded session before previewing. Reuse the existing native plugins and local capture MCP. A returning user sees actual connected grants, scope and expiry before generic installation instructions. A server grant, a plugin installed on this computer and a successful recent preview are distinct states. Loading failures must not appear as no connected agents.

Each action must do what its label promises. If it reveals setup instructions, call it Set up. Copying a command is not proof a picker opened. Advance progress only after the corresponding action actually completes. Preserve the selected draft across retries and sign-in.

A website address can help an agent discover documented capture instructions. It does not install software, grant filesystem access, authenticate an owner, make remote agents able to read a laptop or authorize publication. Show client-specific installation and load status honestly. A hosted MCP cannot discover local session files merely through HTTP.

Privacy choices
Connection is not permission to upload or post. Keep four separate choices:
1. Read a selected local source within the chosen project/session boundary.
2. Prepare a private draft and show the exact outbound fields.
3. Save the selected upload privately; public sharing requires its own reader preview and explicit action.
4. Optionally contribute selected data for a clearly described research purpose, separately from sharing.

Do not upload raw transcripts, prompt bodies, absolute paths, credentials or private repository contents. Do not fetch unrelated private sources. A draft should contain the chosen authored summary, selected counters, selected links/photos and audience.

Local preview means no STRIVE upload before the selected save; it does not promise that a cloud-backed agent's provider sees no tool context. URL fragments are not included in the initial page request but remain readable by browser code and may remain in history. A no-network mode requires genuinely offline rendering and verified transport behavior.

Optional research contribution is a proposed policy requiring review before collection. Default off. Preview the exact fields and describe purpose, linkage, recipients, retention and withdrawal limits. No raw transcripts, automatic retrospective reuse or research permission implied by a public post. Aggregates are not automatically anonymous. Revoking a connection stops future actions, not previously saved data. Deletion/withdrawal promises must match actual storage, backup and published-output handling.

Metrics
Recorded tokens are input plus output from recorded calls in the selected capture. Cache and reasoning subsets must not be added twice. Incomplete usage is unknown, not zero. Captures are client-reported, not provider-attested.

Estimated model cost is a list-price comparison in a named currency using dated model/tier/cache price inputs. It is not the subscription bill or money paid. Omit a complete estimate when necessary price or usage categories are missing. Actual billed spend needs a distinct billing source and matching period.

Elapsed is a timestamp span including waiting. Occupied tool minutes are clock bins containing a tool request, not measured human active time or continuous runtime. Typed messages are messages, not words or keystrokes. Tool requests, file counts and commits indicate recorded activity, not quality or success. Historical reconstructions keep their distinct basis and unknown session measurements. Do not create productivity-per-token scores.

Hackathon context
Associate a project with an explicit event name and official event/entry links. Distinguish owner-declared participation from evidence of actual submission or results. Registration and deadlines do not prove submission; wins need organizer evidence. Keep the run's time window separate from the event/build window and distinguish original entries from later product work.

Agent feedback
An opted-in public project update may receive a clearly labelled agent review answering its specific question. The target owner opts into receiving these reviews; the reviewer owner separately authorizes the actual posting capability. Private-upload access alone does not grant commenting rights.

A review says what it opened, answers the question, identifies a concrete strength or concern and proposes one next test. Cite permitted public sources and distinguish card reading, source inspection and demo use. Never claim a demo was tested without doing so. Self-review must be labelled and is not independent peer recognition. Use bounded quotas and deduplication; no automatic praise chains or synthetic engagement. Ordinary posting should require no model call or extra paid service.

XUDOS
The existing peer-reaction rule excludes self-XUDOS. Any change to that meaning needs an explicit product decision. Keep owner actions useful and avoid offering a button that fails. A private personal mark could be considered separately from peer recognition; it is not an implemented promise.

Feedback and feature ideas
Lead with: What would make you use it?
Offer Suggest a feature · Public and Report a bug or send private feedback · Private as explicit separate routes. Preserve existing private feedback and its saved receipt. Never expose, migrate or publicly summarize old private reports as public ideas without separate specific permission.

Keep the public idea space lightweight: title, problem/use case, requested behavior, real human support, discussion and status with a responsible human owner. Show an honest empty state. No fabricated requests, votes, users, testimonials or seed engagement.

Use New and Most supported views. Support counts distinct eligible signed-in people, is reversible and does not promise implementation. Define self-support and enforce it consistently; agent suggestions never count as human votes. Duplicate merges preserve attribution, links and discussion and count the same person once.

Statuses: Open, Exploring, Planned, Building, Released or Not planned. Give a short reason for changes. Released links to actual available behavior. Popularity informs judgment; it is not a binding commitment.

Agents may draft duplicate matches, source-linked clusters, questions, tradeoffs or experiments from permitted public ideas. Label generated drafts and cite their sources. Private reports stay out of that context by default. A human reviews before public comments, merges, commitments, status changes or code actions. No automatic commits, agent self-voting or paid calls. Treat submitted text as untrusted content rather than executable instructions.

Keep About, Privacy, Terms, Contact and deletion guidance visible in a compact footer after meaningful content. Avoid an artificial empty viewport before the footer. This idea space supports improvements to STRIVE; it does not introduce clubs or general-purpose community features.

Share image
Export the same reader card with immediate preparation feedback. Wait for the selected image list, image decoding and fonts before claiming the result is ready. Preserve selection on errors and offer retry. Measure actual click-to-ready behavior on the same real card, cold and warm, before claiming a speed improvement. Keep private assets out of public shared caches.

Delivery slices and acceptance
1. Entry/privacy: actual grants and retry states; truthful install labels; manual path without Connect; selected capture preview. Verify connection itself makes no upload/public write and retry/sign-in preserves the draft.
2. Project/profile: purpose, visual, change, ask, source labels and profile links. A stranger understands a real update; manual stats stay absent; captured facts retain their basis; complete images fit desktop and phone. Measure share-image waiting and retry.
3. Feedback: compact layout/footer, private reporting and explicit public submission. Verify saved receipts, public confirmation and denial of public access to private feedback. No private-record migration.
4. Ideas: human support, discussion and accountable status. Verify idempotent/reversible support, actor policy, correct duplicate counts, durable links, failed-write behavior and release evidence. No synthetic activity.
5. Agent drafts and optional research: source-linked suggestions with human review; separately approved data policy before collection. Verify generated content cannot broaden authority, vote, change status, commit or incur paid calls by itself. Verify research opt-out produces no contribution and research choices never alter public audience.

Release proof must include actual supported-client and audience journeys, not only fixtures. A first-use trial asks outside builders to create a real private update, correctly explain what leaves their computer, optionally share and respond, then independently return with another update. Record confusion and abandonment as well as completion. Existing held community/group experiments remain outside this revamp's release scope.

Implementation boundaries for the first candidate
This branch implements private manual updates, optional profile details, connection-state clarity and compact UI fixes. The public idea space, research participation and agent peer-review proposals above are product requirements, not shipped capabilities.

A save must be bound to the exact reviewed payload and field allowlist; reject extra capture fields on manual ingestion. Uploaded screenshots are author-selected and must be reviewable in full before save, with removal/redaction available before any public sharing. Never auto-capture a private workspace.

Keep server grants, local installation, successful preview, expired grants and revoked grants distinct in behavior tests. A website cannot infer local installation from imported history.

Research requires a recorded purpose version, specific field selection and separate explicit consent. A materially changed purpose requires renewed consent. Explain withdrawal and deletion limits before participation. Existing public posts or connection grants imply neither research consent nor permission to use private feedback. Per-report permission is required before private feedback enters search, public duplicate matching, share assets or agent drafts.
